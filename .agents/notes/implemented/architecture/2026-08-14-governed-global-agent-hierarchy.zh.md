# Agent Note: 让 agent 更好地遵循指令并停止无效检索

Status: implemented

[English](2026-08-14-governed-global-agent-hierarchy.md) | 中文

## Problem

本草案只处理两个问题：

1. **指令遵循弱。** 用户要求分析、给方案或先确认时，agent 仍可能直接开始实施。
2. **过度思考和过度检索。** 用户已经提供资料或问题已经得到回答，agent 仍可能反复搜索，直到用户手动中止。

Hermes 已经有提示词、Agent 配置、项目配置和插件系统。本草案不新建另一套控制系统，而是把这些功能补全，让用户可以更直接地规定主 Agent 怎么工作、什么时候使用辅助 Agent，以及辅助 Agent 可以使用哪些工具。

### 草案作者原文

> deepseek 的弱点很明显，指令遵循弱 及 过度的思考
>
> 我们要想驾驭它，好马还需配好鞍

## Decision

### 可视化的全局提示词

Hermes 提供全局提示词配置。它的作用类似 Codex 的 `AGENTS.md`：向所有项目提供长期有效的用户指令，但用户直接在设置界面中查看和修改，不需要管理提示词文件。

全局提示词用于记录用户希望 Agent 始终遵守的工作方式，例如：先回答再执行、先使用用户提供的资料、外部检索交给 `researcher`、没有新增信息时停止搜索。

设置界面提供编辑、预览、恢复默认值和启用状态。保存后，从下一次模型请求开始，当前会话和新会话都读取最新提示词，不需要用户重开会话。

### 更直观的多 Agent 配置

Agent 设置包含一个全局主 Agent、四个系统内置辅助 Agent 和用户创建的 Agent。

#### 全局主 Agent

全局主 Agent 提供独立的提示词配置。它负责理解用户要求、决定是否需要辅助 Agent、整合结果并回复用户。

系统提示词会明确告诉主 Agent：有哪些内置辅助 Agent、它们分别负责什么、何时应该使用，以及哪些工作仍由主 Agent 负责。主 Agent 不应自己重复辅助 Agent 已经完成的检索或项目阅读。

#### 四个系统内置辅助 Agent

四个辅助 Agent 使用与普通 Agent 相同的配置结构，可以调整提示词、模型和工具权限，也可以恢复默认值，但不能删除：

- `researcher`：负责外部资料检索；
- `project-explorer`：负责只读查看项目代码、文档和历史；
- `reviewer`：负责检查结果是否符合用户要求；
- `agent-manager`：负责提出 Agent、提示词和工具权限的配置建议。

`researcher` 内置统一的检索规范：先读用户提供的资料，优先使用官方来源，每次搜索必须对应一个没有解决的问题；问题已经回答、资料已经足够或连续搜索没有新增有效信息时停止。主 Agent 需要外部信息时，默认把检索交给 `researcher`，并直接使用其整理后的结果。

`agent-manager` 可以生成或修改 Agent 配置草案，但实际新增 Agent、修改提示词或改变工具权限仍由用户确认。

#### 创建和管理 Agent

用户可以在同一界面创建普通 Agent，并配置名称、用途、提示词、模型、工具权限以及是否允许继续创建辅助 Agent。界面同时显示系统内置 Agent 和用户 Agent，但明确区分两者。

### 项目级提示词

每个项目可以配置自己的提示词，用于记录项目规则、技术要求、工作方式和验证要求。

项目默认同时使用全局提示词和项目提示词。用户可以选择“排除全局提示词”，让该项目只使用项目提示词。这个开关只排除用户配置的全局提示词，不排除 Hermes 必须保留的系统规则。

Hermes 在每次模型请求前读取最新的全局提示词、项目提示词和 Agent 配置。配置发生变化时，Hermes 把新配置写入会话记录，并注明它替代之前的配置。

### 补全插件列表信息

插件列表不能只显示插件名称和启用状态。每个插件还要显示：

- 插件用途；
- 提供的功能和工具；
- 会读取、修改或发送什么内容；
- 是否需要联网或凭据；
- 哪些 Agent 可以使用；
- 当前是否可用，以及不可用的原因；
- 详细文档入口。

插件说明使用直接、可阅读的语言，让用户和 Agent 都能判断插件适合做什么。Agent 配置中的工具权限直接引用这份插件信息，避免只看到难以理解的插件名称。

## Alternatives considered

下面这些做法都能改善一部分问题，但单独使用并不完整。

**只增加一段更长的系统提示词。** 用户仍然无法直观管理全局、项目和不同 Agent 的提示词，也不能清楚管理工具权限。

**只增加更多辅助 Agent。** 如果没有明确的职责、提示词和工具权限，更多 Agent 只会增加重复工作，不能解决过度检索。

**继续只使用项目文件保存提示词。** 普通用户仍然缺少可以直接查看和修改的设置界面，全局规则也需要在每个项目中重复维护。

**新增核心模型工具。** 这两个问题来自提示词、Agent 分工和插件说明不完整。补全现有功能就能处理，不需要扩大核心工具列表。

## Verification

- 设置界面提供可编辑、可预览、可启用和可恢复默认值的全局提示词。
- 设置界面提供一个全局主 Agent、四个不可删除的系统内置辅助 Agent，以及用户创建普通 Agent 的入口。
- 主 Agent 的系统提示词说明四个内置辅助 Agent 的名称、职责和使用时机。
- 每个 Agent 可以单独配置提示词、模型和工具权限；用户创建的 Agent 还可以配置是否允许继续委派。
- `researcher` 遵循统一检索规范，并在问题已回答、资料足够或连续没有新增有效信息时停止。
- 项目可以同时使用全局提示词和项目提示词，也可以明确排除用户配置的全局提示词。
- 插件列表显示用途、功能、读写行为、联网和凭据要求、Agent 使用权、运行状态、失败原因和文档入口。
- 配置修改从下一次模型请求开始作用于当前会话和新会话；会话记录保留每次实际使用的配置。
- 测试覆盖全局提示词继承、项目排除开关、内置 Agent 不可删除、工具权限、检索停止和实时配置更新。

## Consequences

- 全局提示词与项目提示词可能冲突。界面清楚说明项目排除开关移除的内容，模型可见快照记录最终组合结果。
- 四个内置辅助 Agent 增加了设置内容。界面先显示名称和用途，详细提示词、模型和工具权限按需展开。
- 主 Agent 仍可能选择不委派。当前快照会列出每个辅助 Agent，并把外部检索默认交给 `researcher`；真实会话快照固定这条规则。
- `researcher` 仍可能过早停止。默认提示词要求报告已经找到的资料、缺少的信息和停止原因，用户可以明确要求继续检索。
- 插件详情来自包元数据和明确的运行时分类。Cordis 把 Fiber 失败错误保存在内部，因此失败条目会直接提示用户查看 Host 日志，不猜测原因。
